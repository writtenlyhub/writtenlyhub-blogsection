chore(audit): final production readiness optimizations

Implemented end-to-end optimizations and security fixes following a comprehensive 8-phase production readiness audit for the Next.js 15 (Turbopack) + Payload v3 architecture.

Highlights:
1. Performance & Caching:
   - Added an edge-ready cache layer wrapping Payload DB queries to drastically reduce load times.
   - Refactored /api/revalidate route for intelligent, targeted on-demand cache invalidation.
   - Switched to dynamic imports (
ext/dynamic) for heavy charting libraries inside DataGraphBlock.

2. Security & Headers:
   - Injected strict HTTP security headers (nosniff, HSTS, Permissions-Policy, Referrer-Policy) into 
ext.config.ts.
   - Applied path-specific Content Security Policies (Strict for Frontend, Permissive for Payload Admin).
   - Patched potential draft leakage by strictly evaluating eq.user inside Payload access control rules.
   - Configured Auth cookies to enforce secure and sameSite: 'Lax'.

3. SEO & Indexing:
   - Added programmatic sitemap.xml with a dynamic decay algorithm for changefreq and priority.
   - Optimized obots.txt disallow rules for /admin and internal APIs.
   - Standardized og:image cascading fallbacks and canonical URL generation.

4. Accessibility & UI:
   - Self-hosted Material Symbols to eliminate render-blocking external Google Fonts requests.
   - Fixed ria-hidden mismatches and <label> nesting warnings across interactive Modals.

5. Database & Schema:
   - Deployed Drizzle migrations adding publishedAt indexes in PostgreSQL to accelerate sorting.
   - Fixed TypeScript definition mismatches (mapBlogList) that blocked Next.js Turbopack SSG builds.

The codebase now builds natively without memory leaks and has been cleared for staging deployment.
